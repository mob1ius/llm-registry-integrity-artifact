Corpus v1
=========

Generated by `scripts/build_corpus.py`. Output: `corpus_v1.json` (40 entries),
`corpus_v1_excluded.json` (233 entries, with reasons).

5 anchors, chosen to span developers/architectures: Llama-3.1-8B-Instruct,
Mistral-7B-Instruct-v0.3, Qwen2.5-7B-Instruct, gemma-2-9b-it,
Phi-3-mini-4k-instruct.

For each anchor: search HF for GGUF-tagged repos matching the name, filter,
*then* bucket by popularity. Filtering after bucketing would give you a
"long tail" that's really just "everything we didn't filter yet," which
isn't the comparison we want.

Two filters:

1. Keyword filter on repo name -- excludes abliterat/uncensor/dpo/wpo/orpo/
   rp-/roleplay/merge/slerp/distill/etc. These are legit derivatives, not
   re-quantizations of the actual checkpoint.
2. `cardData.base_model` match against the canonical checkpoint ID (with the
   usual naming aliases -- Llama-3.1 vs Meta-Llama-3.1 etc).

Needed both. `base_model` on its own isn't enough -- HF's convention for that
field is "built from X," and a DPO pass built from the base model still
declares the base model there. First pass without the keyword filter let
`gemma-2-9b-it-DPO` and `gemma-2-9b-it-WPO-HB` straight through. Caught it
before anything got written to the corpus.

Top 3 by downloads per anchor -> high_popularity. Bottom 4 with nonzero
downloads -> long_tail. Plus the matching official Ollama tag, pulled via
the registry manifest (no model download needed for that part).

Composition: 40 entries total. 15 high-popularity HF repos, 20 long-tail,
5 official. Long-tail accounts are genuinely tiny -- YorkieOH10,
NonMiFrega, tokoin, alal123, edsoncarvalhointuria -- 86 to ~2,900
downloads vs 66k-288k on the popular side. This is the population the
pre-flight check flagged as where divergence risk was likely concentrated.

Limitations: N=40 is pilot scale, not the real N (targeting 150-300).
Keyword filtering is a heuristic and can go wrong both ways -- a clean repo
with an unlucky name substring, or a derivative that just doesn't say so in
its name. Should spot-check a sample by hand before trusting the full run.
Popularity here is HF download count only; didn't pull Ollama tag counts
since their public API doesn't expose those the same way.
